# Prefill and decode throughput comparison

The [README table](../README.md) reports three conventional shapes on the target HP Envy 17: prefill of 512 or 2048 tokens (`pp`) and 128 decode steps from an empty context (`tg128`). It uses the same Gemma 4 26B-A4B IT QAT UD-Q4_K_XL GGUF for all three engines. The model's SHA-256 is `a7c5bc715f5ff8e99a3e8901ce7d2b42b402c669bf24f7c5250747633d0f5891`.

## Check the published numbers

Run `python3 -B bench/compare_pp_tg_verify.py` from the repository root. This checks all 27 measurements in [compare_pp_tg-20260910.csv](compare_pp_tg-20260910.csv), computes `tokens / seconds` for each repetition, takes the median of three rates, rounds to two decimals, and checks the README table. The CSV is a privacy-filtered extract of the nine `stdout.log` files from the September 10–11, 2026 campaign. Its `standard-*` run names are the original identifiers retained for provenance. Each source run finished with exit code zero and without a guard abort. Load and warmup measurements are excluded; no measured repetition is discarded. The original full logs remain private because system snapshots and commands contain local device information and paths.

The historical Xenolith measurements used base commit `302612e0944c50668d1f231944ba1c6e2a4ca6b3` with preexisting local changes; the GPU kernel source is unchanged in this public release. The llama.cpp measurements used commit `434ddbbc0e30522e897670681e503b797c12b7c1`. These are measurements from that campaign, not a promise that a new run will produce identical rates.

## Repeat on the target machine

Set `XENOLITH_MODEL` to the GGUF path, `XENOLITH_LLAMA_SOURCE` to a llama.cpp checkout at the commit above with unmodified tracked files, and `XENOLITH_BENCH_OUTPUT` to a fresh directory outside both source trees. Then run `bash bench/compare_pp_tg.sh`. Run `bash bench/compare_pp_tg.sh --help` to see the command without starting a build or measurement.

The script checks the GGUF hash, builds `bench/compare_pp_tg_xe` and `bench/compare_pp_tg_tokens` through the Makefile, builds the pinned llama.cpp libraries with CMake, and compiles the same C harness with `-DLLAMA` into the output directory. It checks the generated token-sequence hash, runs the nine guarded cases, then prints their medians with `compare_pp_tg_verify.py --runs`. It does not replace the historical CSV or README results. The output directory is private by default: its command, environment, and system logs may contain local paths and machine details.

The common [compare_pp_tg.c](compare_pp_tg.c) harness uses a fixed sequence generated by [compare_pp_tg_tokens.c](compare_pp_tg_tokens.c): glibc `srand(1)`, first token 2, then `rand() % 262144`. It performs one full-shape warmup for prefill, or a one-token warmup for `tg128`; it resets the context between three timed repetitions in the same process. Decode consumes fixed token IDs, without autoregressive sampling. Throughput uses wall-clock time and excludes model loading and warmup. The llama.cpp context request is `depth + generated tokens + 512`, so its allocated context differs by shape even though each backend's processing profile is fixed.

| Backend | Fixed processing profile |
|---|---|
| Xenolith | Level Zero prefill, six decode workers on the physical P-cores. |
| llama.cpp CPU | CPU only, mmap, no BLAS, six generation threads, twenty batch threads, `taskset -c 0-19`. |
| llama.cpp Vulkan | Full GPU offload (`NGL=99`), Flash Attention off, f16 KV, microbatch 1024, one CPU thread, `taskset -c 0-19`. |

The runner waits for AC power, at least 24 GiB `MemAvailable`, and cooldown toward 60 °C before each case; after three minutes it may proceed below 90 °C. The public `bench_guard` stops immediately above its configured 97 °C limit. The historical guard instead required three consecutive hot samples or one sample above 100.5 °C. Temperature, clocks, throttling, memory pressure, swap, and filesystem cache can still change measured throughput. The historical campaign did not control clock frequencies or cold filesystem cache, and three samples do not give a confidence interval.
